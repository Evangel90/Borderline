## Decisions (from the user, keep them)

1. **Every claim needs an exact quote** with its chunk ID, verified verbatim (design rule 2).
2. **Nothing is a legal conclusion.** No legal professional reviews the output. Use "candidate", never "finding" or "violation", unless evidence criteria are met, and even then say it is unreviewed.
3. **Arabic quotes:** quote the Arabic verbatim and add an English translation labelled "unofficial translation by the project, not an official text". Never quote only the translation. If extracted Arabic is garbled (PyMuPDF ligature errors, e.g. "اإلصدار"), do not retype it as a verbatim quote.

6. **Agents should make decisions based on the rules**, with code checking their work (step 1). The user wants the AI to decide, not a fixed table.

## Next steps

### 1. AI decides, code checks the quote (biggest; do first)

Goal: agents answer the three liaison questions themselves, and code verifies them.

- The sending agent (or a dedicated liaison reviewer agent; choose one and explain why) answers each question YES / NO / UNCLEAR with an exact quote and chunk ID.
- Code checks each quote appears verbatim in that chunk (normalize whitespace only). A missing, altered or uncited quote turns that answer into UNCLEAR. Record the check result in the log.
- Hard floor in code: a request carrying patient data never routes without a verified legal-basis quote, whatever the agent says (design rule 7).
- Every UNCLEAR or NO gets a type: `policy_gap` (law silent), `implementation_gap` (law needs an instrument that does not exist), `conflict` (laws point different ways), or `missing_evidence` (we lack the document). Only the first three can become gap candidates; `missing_evidence` is our homework.
- Arabic quotes are checked against the Arabic chunk and displayed with a labelled translation (decision 3).
- Keep the current YAML answers as a fallback or a test fixture; decide which, and say so.
- Tests: verified quote routes, fabricated quote becomes UNCLEAR, patient data without a basis is always blocked, the type is recorded, Arabic quote handling.

Done when the drill can run with agent-made liaison decisions and every decision's quote check is in the hash-chained log.

### 2. Evidence-sufficiency rule in code

A candidate becomes a supported gap only when all of these hold:

- every quote verifies;
- a search record exists in `gaps/searches/`;
- a verified global comparator is quoted;
- no **obtainable** known-missing document could refute it.

Split known-missing documents into two kinds. **Unobtainable after documented attempts** (Resolution 51) does not block; record it as a separate accessibility candidate, worded "not publicly accessible to the project after documented attempts", not "does not exist publicly". **Obtainable but not yet fetched** blocks. Missing documents never stop the drill from running; they only affect candidate status.

## Known traps

- `AE-DATA-PDPL-2021` (unofficial English and Japanese translation) is excluded from retrieval but kept so old runs stay traceable. Use `AE-DATA-PDPL-2021-EN`.
- DHA's English policies say "UAE Information Office" where the Arabic says "Emirates Data Office", and call Resolution 51 a "Cabinet Decision" (it is ministerial).
- MDCG 2020-3 applies only to legacy devices on MDD/AIMDD certificates; it is cited as a worked example, not as the rule for MDR-certified devices (that is MDR Annex IX 4.10).
- Neither Switzerland nor the UAE is on the IMDRF N14 Annex 1 participant list (2025). Earlier in the session this was wrongly assumed for Switzerland.
- UAE government portals (uaelegislation.gov.ae, mohap.gov.ae) refuse automated downloads; dha.gov.ae and doh.gov.ae work. The user can download manually.
- `relevant_authorities` in institution profiles is not used by the engine for retrieval (design rule 5 is not implemented).
- `make ingest` rewrites every chunk pack from `data/sources.csv`; check the diff touches only the documents you meant to change.
- When editing `data/sources.csv`, change only the lines you mean to. `csv.DictWriter` over the whole file adds trailing empty columns to every row.
